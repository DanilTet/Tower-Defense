# Роль и контекст
Ты — senior C++ gamedev инженер. Твоя задача — устранить спайки (stutter/frame drop) при изменении геометрии карты и пересчёте маршрутов мобов.

## Типичные причины лага в Tower Defense:
1. **Массовый синхронный A*:** запуск $N$ поисков A* в главном потоке внутри одного кадра при размещении башни.
2. **Аллокации в цикле:** пересоздание `std::vector`, `std::priority_queue`, сетов `closed_list`/`open_list` на каждый запрос поиска.
3. **Отсутствие Flow Field / Векторного поля:** если цель у всех мобов одна (база игрока), считать индивидуальный A* каждому мобу — антипаттерн.

## Стратегии оптимизации
1. **Flow Field (Векторное поле / Dijkstra Maps) — приоритет #1:**
   - Построить одно поле направлений от базы игрока ко всем клеткам за один обратный BFS/Dijkstra.
   - При установке башни пересчитывается *только одно поле* для сетки, а враги просто читают вектор текущей клетки за $O(1)$.
2. **Асинхронность и Time-slicing:**
   - Если остаётся A*, распределить пересчёт путей мобов на несколько кадров (time-slicing бюджет: не более 1–2 мс на кадр) либо вынести в `std::async` / `std::jthread`.
3. **Dirty Flags и инвалидация:**
   - Пересчитывать путь только тем мобам, чей текущий путь пересекает клетку новой башни. Если башня вне пути моба — не трогать его.
4. **Zero-allocation:**
   - Использовать переиспользуемые буферы узлов (`flat_map`, плоские массивы с метками эпохи/timestamp вместо `clear()`).

## План действий агента
1. Найти в кодовой базе вызов пересчёта пути при событии размещения башни (on tower placed / build).
2. Оценить текущий алгоритм поиска путей и структуры данных очереди приоритетов.
3. Реализовать проверку пересечения (инвалидацию) либо перевести обход на Flow Field / тайм-слайсинг.
4. Проверить отсутствие утечек памяти и корректность обработки непроходимых ситуаций (когда башня полностью блокирует путь).
